Papyrus Catch-Up v0.3.1

낮은 FPS에서의 스카이림 스크립트 밀림(스크립트 랙) 완화 SKSE 플러그인

먼저 분명히 말씀드립니다. 이 모드는 FPS를 올리는 모드가 아닙니다.

무거운 장소나 전투에서 엔진 FPS가 50 아래로 떨어질 때 스크립트 반응이 한 박자씩 늦어지는 현상(스크립트 랙)을 줄이는 모드입니다. 엔진 FPS가 50 이상일 때는 개입하지 않고 순정 그대로 돕니다. (DLSS·FSR·Lossless Scaling 프레임 생성을 쓰시는 분은 화면 표시 FPS가 아니라 엔진 원본 FPS 기준입니다.)

왜 50 FPS 아래에서 스크립트가 밀리나요?

스카이림의 파피루스(Papyrus) 스크립트가 게임 상태를 조회하거나 부르는 많은 네이티브 함수는 작업 스레드에서 바로 실행되지 못하고 대기열을 거쳐 다음 프레임의 VM 업데이트에서 처리됩니다. 그래서 이런 호출이 10번 이어지는 스크립트는 60 FPS에서 0.17초 걸리던 일이 30 FPS에서는 0.33초, 20 FPS에서는 0.5초로 프레임에 정비례해 늦어집니다.

Papyrus Catch-Up은 최근 0.5초 평균 엔진 FPS가 50 아래로 내려갔을 때만, 엔진의 VM update 작업 안에서 순정 VM 순환을 같은 프레임에 추가로 실행해 밀린 호출을 따라잡습니다. 이때 구현을 직접 디스어셈블해 부수 효과가 없음을 확인한 읽기 함수(게임 30종 + SKSE 2.2.8 14종), 자동 프로퍼티 읽기, 산술·문자열 도우미만 같은 프레임 연쇄를 허용하고, 상태를 바꾸는 호출 뒤에는 순정처럼 다음 프레임을 기다립니다.

이런 분께 체감이 됩니다

  • 무거운 도시, 대규모 전투, 사양 한계 등으로 엔진 FPS가 30~49 구간으로 자주 내려가는 환경
  • 장비 이벤트·전투·생존·동료·장면 계열 등 스크립트가 많은 대형 모드팩을 돌리는 환경
  • 무거운 구간에서 MCM 메뉴 열기, 장비 교체 효과, 장면·스킬 발동이 한참 뒤에 따라오는 답답함을 겪는 분

엔진 FPS가 거의 항상 55~60 이상 유지되는 고사양 환경에서는 개입할 일이 거의 없어 체감이 작거나 없습니다.

설치·제거 및 요구 사항

  • 지원 버전 (단일 DLL): Skyrim SE 1.5.97 및 AE 1.6.640 / 1.6.659(GOG) / 1.6.1130 / 1.6.1170 / 1.6.1179(GOG)을 지원합니다. AE 1.7.x는 아직 미지원이며, 목록에 없는 버전(1.7.x 포함)에서는 플러그인이 스스로 로드를 거절하고, 목록 안의 버전이라도 훅 지점의 기계어가 확인한 것과 다르면 훅을 걸지 않고 꺼진 채 로그만 남깁니다.
  • 버전별 검증 현황: AE 1.6.1170은 제작자 환경에서 실제로 돌려 확인했습니다(아래 시험 범위 안에서). SE 1.5.97은 실행 파일을 디스어셈블해 훅 지점과 읽기 함수를 대조했습니다. AE 1.6.640 / 1.6.659 / 1.6.1130 / 1.6.1179는 실행 파일이 없어, 쓰는 주소 ID가 모두 있는지만 확인했고 훅 지점은 게임 안에서 1.6.1170과 같은 기계어일 때만 켜집니다. 이 버전들의 실제 인게임 구동 확인은 이번 실험판에서 처음 받습니다. (1.5.97 / 1.6.640 실행 성공·실패 로그 제보를 특히 환영합니다!)
  • 필수 모드: 각 게임 버전에 맞는 SKSE64와 Address Library for SKSE Plugins (SE 1.5.97은 SE용, AE 1.6.x는 AE용). 참고로 SKSE 네이티브 14종은 1.6.1170 + SKSE 2.2.8에서만 읽기로 인정되며, 1.5.97·1.6.640 등에서는 게임 읽기 30종 + 자동 프로퍼티 읽기 + 게임 도우미만 읽기로 인정합니다(효과가 그만큼 작을 수 있습니다).
  • 설치: ZIP 파일을 MO2에서 일반 모드처럼 설치하고 활성화하면 바로 켜집니다. (이전에 v0.3.0이나 AdaptivePapyrusBudget 테스트판을 쓰셨다면 교체해 주세요.)
  • 제거 안전성: 세이브 파일에 아무것도 쓰지 않는 순수 SKSE DLL입니다. 플러그인 전용 데이터가 세이브에 남지 않으므로 끄고 빼도 세이브를 못 여는 일은 없습니다. 다만 켜 둔 동안 스크립트가 바꾼 게임 상태(퀘스트 진행 등)는 세이브에 그대로 남고, 플러그인을 뺀 뒤 이어서 진행하는 경우는 따로 시험하지 않았습니다.
  • 호환성: SSE Display Tweaks, Papyrus Tweaks NG와 함께 쓴 상태로 시험했습니다(Papyrus Tweaks NG의 bSpeedUpNativeCalls 조합은 미시험). 설치할 때 훅 지점의 기계어를 확인하고 추가 순환마다 자기 훅이 그대로인지 보므로, 예상과 다른 실행 파일이나 나중에 같은 자리를 덮은 플러그인을 만나면 스스로 꺼지고 로그를 남깁니다. 다른 곳을 고쳐 VM 동작을 바꾸는 플러그인까지 잡지는 못합니다.

주요 INI 설정

SKSE/Plugins/PapyrusCatchUp.ini

항목 기본값 설명
Mode accelerate off(끔) / carried(예산 이월분만) / accelerate(읽기 연쇄 가속)
EngageBelowFPS 50 최근 0.5초 평균 엔진 FPS가 이 값 아래일 때만 개입
TargetFPS 84 개입 시 복구할 목표 VM 순환 속도(Hz). 40대 FPS에서도 체감되도록 84가 기본이며, 보수적으로 순정 60 FPS 수준만 원하시면 60으로 낮추시면 됩니다.
SkipWaitingCalls true 추가 순환에서 다음 프레임을 기다려야 하는 호출이 대기열 맨 앞에 있어도 멈추지 않고, 그 뒤의 호출을 먼저 실행합니다. 효과가 훨씬 크지만, 다른 스크립트가 먼저 대기열에 넣은 호출보다 뒤의 호출이 먼저 실행될 수 있습니다(순정에는 없는 순서). 기다린 호출끼리의 순서는 지켜집니다. 순서 민감 퀘스트·모드에서 이상이 보이면 false로 끄실 수 있습니다.
MaxExtraMS 2.0 프레임당 새 추가 순환을 시작하지 않는 기준 시간(ms). 이미 시작한 순환은 끝까지 돌기 때문에 넘을 수 있습니다(제작자 플레이에서 가장 길었던 프레임은 약 16ms). 상한의 2배를 넘으면 3초간 자동 휴식하고, 그 프레임에 실행된 스크립트 함수 이름을 로그에 남깁니다(그중 어느 것이 느렸는지까지는 가리지 못합니다).

※ 세이브 로드·로딩 화면 직후 10초 동안은 초기 스크립트 폭주를 피하기 위해 자동으로 개입을 보류합니다.

아직 확인하지 못한 점 (실험판 주의)

  • 모드·퀘스트 범위: 지금까지 확인한 것은 한 가지 대형 모드팩 구성과 Alduin's Wall 여관 장면·장비 변경·셀 이동입니다. 다른 퀘스트나 서드파티 모드에서 순정과 다른 실행 순서에 민감한 스크립트가 나올 수 있습니다.
  • CPU 100% 병목 환경: 실플레이 32~49 FPS 구간에서 프레임당 추가 비용은 평균 0.07~0.19 ms였지만, CPU가 완전히 포화된 저사양 환경에서의 프레임타임 영향은 이번 실험판 로그로 함께 확인하려 합니다.
  • 원인 모를 로딩 멈춤 1건: 퀘스트 시험 초기에 SkipWaitingCalls=true 회차 하나가 로딩 화면에서 멈췄고 원인을 찾지 못했습니다. 그 뒤 본 실행 30회와 저장·재로드 12회에서는 다시 나지 않았지만, 로딩 중 멈춤이 보이면 이 옵션을 false로 바꿔 보시고 알려 주세요.
  • Papyrus Tweaks 미사용(순정 연산 한도 100) 환경: 시험 환경은 iMaxOpsPerFrame=500 기준이었습니다.

테스터분들께 듣고 싶은 것

  1. 엔진 FPS가 50 아래로 내려가는 구간에서 MCM·장비·전투·장면 반응이 빨라졌다고 체감되시나요?
  2. 반대로 툭 끊김(스터터링)이나 프레임 저하가 새로 느껴지는 구간이 있나요?
  3. 퀘스트 진행 꼬임, 장면 멈춤, CTD 같은 이상 증상이 나오면 꼭 알려 주세요.
